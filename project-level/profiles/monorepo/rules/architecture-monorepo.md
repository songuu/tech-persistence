# Monorepo 架构规则

> Claude Code 只在 `.claude/project-standards.json` 启用 `monorepo` 时应用本规则。

## 包边界与所有权

- 每个 app、service、package 或 tool 有明确职责、owner、公共入口和验证命令；根目录只承载共享编排。
- 包之间通过声明的公共 API 交互，禁止深层导入、反向依赖和循环依赖；共享包不得成为无边界杂物箱。
- 业务专用代码留在所属包，只有稳定且被多方使用的能力才能进入共享层。

## 任务图与配置

- 构建、测试、生成和发布依赖由 workspace 任务图表达，输入、输出和缓存键完整；不依赖人工执行顺序。
- 共享 lint、类型和构建配置提供基线，包可通过记录原因的窄扩展覆盖，不能复制后静默漂移。
- 根锁文件和 workspace 声明是依赖解析权威；跨包版本关系和生成产物 owner 必须唯一。

## 跨包变更

- 修改公共契约时先识别全部消费者，同一变更内更新实现、类型、文档、测试和受影响包。
- 只运行 changed 范围不能证明跨包安全时，扩大到依赖方与反向依赖方；缓存命中也要有可追溯输入。
- 独立发布与统一发布策略必须明确，版本、变更记录和发布顺序与实际兼容承诺一致。
