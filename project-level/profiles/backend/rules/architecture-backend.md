# 后端架构规则

> Claude Code 只在 `.claude/project-standards.json` 启用 `backend` 时应用本规则。

## 分层边界

- 先确认仓库实际采用分层、vertical slice、serverless、事件驱动或混合结构；保持既有有效边界，不为简单
  用例强加 Domain/Repository 模板。
- HTTP、RPC、消息、定时任务等入口只处理协议、身份、输入校验与结果映射；业务不变量进入可独立测试的
  application、domain 或 feature 模块。
- 持久化与外部 SDK 细节留在明确的 adapter/feature 边界；只有存在多个实现或需要隔离领域语义时才抽象
  Repository，避免无价值转发层。
- 依赖方向不得绕过已存在的业务不变量和授权边界；小型 CRUD 可使用 feature-local 数据访问，但要显式
  声明事务、校验与测试边界。

## 数据库与迁移

- Schema 变更使用可审计迁移，明确前向、回滚或不可回滚策略，以及老版本并存窗口。
- 大表回填与约束收紧分阶段执行，评估锁、索引、事务、批次、幂等和重试；生产数据不靠手工补齐。
- 查询同时验证正确性、边界条件和成本；事务边界围绕业务原子性，而不是方便的代码块。

## 认证与授权

- 认证确认主体，授权校验主体对具体资源和动作的权限；两者都在可信服务端边界执行。
- 默认拒绝，最小权限；对象级权限不能只依赖路由或客户端隐藏，敏感失败信息避免泄露资源存在性。
- 凭据和会话有生命周期、吊销与轮换策略，日志不得记录秘密或完整敏感载荷。

## 可观测性与可靠性

- 日志、指标和追踪使用稳定事件名与关联标识，覆盖入口、依赖、重试和失败原因。
- 外部调用设置超时、取消、有限重试和幂等边界；只对可安全重放的失败重试并保留原始上下文。
- 健康检查区分进程存活与依赖就绪，降级和故障恢复行为必须可观测。
- 消息与事件处理显式定义幂等键、顺序、重放、确认、死信和 poison message 策略；跨数据库与消息系统的
  一致性使用可证明的事务、outbox/inbox 或补偿边界，不假定 exactly-once。

## API 契约与验证

- API 契约明确请求、响应、错误、分页、幂等和兼容策略；实现、文档和消费者使用同一权威定义。
- 破坏性契约变更需要迁移窗口或版本策略，并验证至少一个真实消费者路径。
- 最窄验证从领域单元测试开始，再覆盖 repository、transport、迁移、鉴权失败和契约集成测试。
