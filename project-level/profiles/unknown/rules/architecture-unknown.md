# 未知架构发现规则

> `.claude/project-standards.json` 启用 `unknown` 表示证据不足，不表示项目没有架构。

## Discovery first

- 只读检查顶层目录、依赖清单、workspace 配置、入口、构建脚本、测试、部署文件和 README。
- 从实际导入、调用与运行命令识别模块职责和数据流；目录名、模板说明和历史文档只能作为候选线索。
- 输出候选 profile、支持证据、冲突证据和未知项，区分“文件存在”与“真实运行路径已验证”。

## 停止边界

- 未确认 profile 前只应用 `base` 与本规则，不生成框架专属规范，不重排目录，也不引入依赖。
- 若多个架构候选互斥、入口缺失或仓库仅有占位内容，停止推断并请求最小必要上下文。
- 不把当前 runtime 的项目规范目录或顶层 Agent 说明本身当作项目架构证据，避免自证循环。

## 完成条件

- 至少找到一个可复核的源码、依赖或运行入口证据，才能把 `unknown` 替换为具体 profile。
- profile 选择允许叠加；前后端共存、多包或 Agent 运行时应分别保留证据，不强行归为单一类型。
- 完成发现后重新生成 manifest，并独立审计 profiles、evidence、assets、hash 与双运行时 parity。
