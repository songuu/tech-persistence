# Web 前端架构规则

> Claude Code 只在 `.claude/project-standards.json` 启用 `frontend` 时应用本规则。

本画像覆盖浏览器前端和以 Web 技术为核心的桌面/移动外壳；原生 Swift/Kotlin/Flutter 等工程需要另行
读取其平台规范，不能用本规则替代签名、权限、生命周期和发布要求。

## 组件与交互

- 页面负责组合，领域逻辑进入可测试的业务模块；组件以单一职责、显式输入输出和组合复用为主。
- 优先复用项目设计系统与基础组件；业务组件不得私自复制一套通用控件行为。
- 异步交互必须呈现加载、空、失败、成功和重试状态，危险操作提供确认或可恢复路径。

## 样式与设计系统

- 颜色、字号、间距、圆角和层级使用语义 token；局部覆盖只表达该场景独有差异。
- 响应式布局从内容约束出发，验证窄屏、长文本、缩放和深浅主题，不依赖固定设备尺寸。
- 样式修复先定位 token、组件基座或页面作用域，避免用高优先级选择器掩盖根因。

## 状态与数据

- 区分组件局部状态、派生状态、服务端状态和跨页面状态；同一事实只保留一个权威来源。
- 派生值在读取时计算，不通过同步副作用维护副本；持久化状态要有 schema、版本和失效策略。
- 服务端数据的缓存键、刷新、并发、乐观更新和回滚策略必须与业务一致。

## API client 与 BFF

- API client 集中处理地址、认证注入、超时、取消、序列化和错误归一化，业务组件不直接拼协议细节。
- 请求与响应在边界处校验；错误保留状态、业务码和关联上下文，但不向界面泄露敏感内部信息。
- BFF 只做面向界面的鉴权、聚合和协议适配；服务端密钥不得进入客户端，核心领域规则不得复制到 BFF。

## i18n 与可访问性

- 用户可见文本进入本地化资源，避免靠字符串拼接表达语法；日期、数字和复数遵循 locale。
- 使用语义结构、可访问名称和可预测焦点；键盘可完成全部关键流程，状态变化能被辅助技术感知。
- 颜色不是唯一状态信号，文本对比度、触控目标和减少动画偏好必须可验证。

## 构建与验证

- 使用仓库声明的 lint、类型、测试和生产构建命令；不以开发服务器可启动替代生产构建证据。
- 对路由、数据边界和关键交互补组件或端到端回归；检查首屏、代码拆分和静态资源是否意外膨胀。
- 涉及服务端渲染或预渲染时，验证服务端与客户端输出一致，浏览器专属能力有明确边界。
