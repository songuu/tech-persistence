# 数据工程架构规则

> Claude Code 只在 `.claude/project-standards.json` 启用 `data` 时应用本规则。

## 数据契约与血缘

- 数据集必须有明确 owner、schema、主键、时间语义、更新频率、质量目标和兼容策略。
- 原始、清洗、业务和服务层职责分开；每个派生字段能追溯到输入、转换版本和运行批次。
- Schema 演进先验证生产者与消费者兼容性，禁止把隐式列顺序或未声明空值当成契约。

## Pipeline 边界

- 任务按可重放的业务分区设计，输入、输出、checkpoint 和幂等键显式；重试不得重复产生副作用。
- 编排层负责依赖与调度，转换层负责数据逻辑，连接器负责外部协议，三者不互相嵌入私有实现。
- 回填、晚到数据和部分失败有独立策略；大范围重算先估算容量、成本、锁和下游影响。

## 质量、安全与验证

- 在入口、关键转换和发布边界验证完整性、唯一性、范围、引用关系、时效与分布漂移。
- 敏感数据按最小采集、最小权限、脱敏、保留期和删除要求处理，非生产环境不得复制无保护生产数据。
- 测试覆盖转换样例、空值、重复、乱序、时区、Schema 演进和幂等重跑；运行成功需由目标数据读回证明。
