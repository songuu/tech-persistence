# 全栈交叉边界规则

> Claude Code 只在 `.claude/project-standards.json` 启用 `fullstack` 时应用本规则，并同时遵循已启用的前端与后端规则。

## 信任与职责边界

- 先按真实拓扑识别浏览器、edge/serverless、BFF、服务、worker、消息系统和数据库中实际存在的信任域；
  身份与输入跨域时重新验证，不能信任客户端状态，也不虚构项目不存在的层。
- 前端负责交互与展示；若存在 BFF、领域服务或异步 worker，其职责分别限制在界面聚合、业务不变量和后台
  执行。小型同构应用可合并部署，但仍须保持客户端、可信服务端与持久化边界。
- 服务端秘密、内部错误和存储模型不得进入客户端包；共享代码只包含可安全跨运行时执行的契约与纯逻辑。

## 共享契约

- 请求、响应、错误和事件 schema 有单一权威来源；生成客户端是投影，禁止前后端各自维护近似类型。
- 契约演进考虑旧客户端、滚动部署和缓存数据，先扩展兼容再迁移消费者，最后移除旧字段。
- 时间、金额、标识、分页、空值和枚举在全链路保持同一语义，序列化边界有回归样例。

## 端到端一致性

- 一个用户动作使用可关联标识贯穿界面、请求、服务与异步任务；错误对用户可行动，对运维可诊断。
- 乐观更新、重试与后台任务必须共享幂等和最终一致性策略，失败时不会产生重复写入或虚假成功。
- 交付验证覆盖关键用户路径、鉴权失败、契约兼容、迁移窗口和前后端独立部署顺序。
