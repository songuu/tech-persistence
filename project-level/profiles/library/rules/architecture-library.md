# 可复用库架构规则

> Claude Code 只在 `.claude/project-standards.json` 启用 `library` 时应用本规则。

## 公共 API

- 公共入口保持最小、明确且有文档；内部模块默认不导出，消费者不得依赖未承诺的文件路径。
- 类型、错误、同步/异步、资源所有权和线程或并发语义都是契约的一部分，不只关注函数签名。
- 新抽象至少由两个真实用例证明；针对单一调用方的便利逻辑留在调用方，避免扩大长期兼容面。

## 兼容性与依赖

- 破坏性变更显式标注并提供迁移说明；弃用先有替代方案、告警和合理迁移窗口。
- 运行依赖保持最少，宿主应提供的能力使用 peer 或适配边界表达；不要让开发工具泄漏到运行产物。
- 平台相关逻辑隔离在适配器中，核心 API 不暴露特定包管理器、框架或文件系统假设。

## 打包、发布与验证

- 从消费者视角验证入口、类型、模块格式、资源文件和 tree-shaking；源码测试通过不能替代安装包测试。
- 发布产物可复现并只含声明文件，版本、变更记录、许可证和来源可追溯；禁止从脏工作区临时发布。
- 测试覆盖公共 API、错误路径、兼容样例和最小消费者工程；支持矩阵以实际自动化证据为准。
