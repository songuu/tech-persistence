# 基础设施架构规则

> Codex 只在 `.codex/project-standards.json` 启用 `infrastructure` 时应用本规则。

## 权威来源与边界

- 基础设施、策略和部署配置以版本化声明为权威来源；禁止用未记录的控制台操作维持长期状态。
- 环境差异通过明确参数和受控密钥引用表达，不复制整套配置，也不把秘密写入仓库或构建产物。
- 模块输出稳定契约，环境组合只依赖公开输出；避免跨栈读取内部状态和循环依赖。

## 安全与交付

- 身份、网络和数据访问默认拒绝并遵循最小权限；管理面与业务面分离，审计记录不可由工作负载自行覆盖。
- 构建一次、按不可变标识晋级；依赖和基础镜像可追溯，生产部署不依赖浮动版本。
- 计划与应用分离，高风险或破坏性差异必须人工审阅；并发更新有锁、漂移检测和明确 owner。

## 可靠性与验证

- 服务声明资源边界、健康检查、超时、滚动策略、容量假设和降级方式，失败不会无限重启或重试。
- 每次变更说明备份、回滚或前滚路径；先在低风险环境验证，再观察指标、日志和告警后扩大。
- 验证至少覆盖静态检查、计划差异、策略、安全扫描和部署后读回；本地渲染成功不等于云端已应用。
