## 1. 项目背景与设计哲学

在现代 AI 辅助研发与组织协同场景中，团队与个人普遍面临三大核心瓶颈：
1. **隐性认知难以沉淀：** 高阶工程师（架构师、SRE、安全专家）的核心竞争力不在于代码语法，而在于其 **Context 构建策略、架构边界断言、排错时序逻辑及防御性约束**。
2. **客观事实与主观对话脱节：** 纯对话记录存在大量随性、试错与噪音，而 **Git 提交历史（Commits、Diffs、PR Review 评审、Revert/Hotfix）** 则是经过团队评审与生产验证的“绝对真理源（Ground Truth）”。
3. **Agent 行为失控与过度泛化：** 缺乏确定性约束，AI Agent 在执行复杂任务时容易“自作聪明”，违背既有架构分层、滥用状态或盲目臆造推断。

### 核心设计哲学：融合三大开源范式 + Git 生产证据链
本系统（Cognitive Skill Engine，简称 **CSE**）在融合开源范式的基础上，将 Git 轨迹作为不可或缺的基石：
- **融合 `yourself-skill` 的私域解构与记忆分层：** 采用 `Memory + 5层 Persona` 双层架构，支持运行时纠偏与历史版本回滚。
- **融合 `nuwa-skill` 的心智模型与认知操作系统提取：** 采用 6 路并行分析与严格的 **TV 三重验证机制**（跨域性、预测力、排他独特性）。
- **融合 `cangjie-skill` 的 RIA-TV++ 结构化 SOP 与对抗压测：** 采用 `R-I-A2-E-B` 结构化封装与 **Darwin 棘轮演进机制**。
- **引入 Git 生产证据链 (Git Ground Truth)：** 将 Git Diffs、PR 对抗评审与故障修复记录作为提炼“硬规则”与“反模式”的核心客观事实源。

## 2. Git 历史作为核心认知资产的蒸馏价值

Git 记录是提炼工程师技能与架构约束最具含金量的数据资产。系统重点从以下 4 个 Git 核心维度进行蒸馏提取：

### 2.1 PR Review 评审对抗记录（提炼 Hard Rules 与 Anti-Patterns 的金矿）
- **资深工程师的 Block / Request Changes 意见：** 资深研发在评审中指出的“此处存在并发竞争”、“禁止在循环中触发网络请求”、“缺少事务边界回滚”，可直接提炼为**不可违背的 Hard Rules**。
- **反复修改的 Diff 片段：** 开发者从被打回到最终合入之间的代码改动，直观反映了团队架构规范对低质量代码的修正过程。

### 2.2 原子化 Commit 拆解序列（提炼 Decomposition 任务拆解力与 SOP）
- **复杂需求的提交演进图：** 高阶工程师处理复杂功能时，通常拆解为若干清晰的渐进式 Commit：
  `[Step 1: 数据模型与类型契约定义] → [Step 2: 核心状态机/业务逻辑实现] → [Step 3: 边界异常捕获与重试] → [Step 4: 单元测试覆盖]`。
- **提炼价值：** 将这种演进逻辑直接转化为 Agent 执行任务的标准分步 SOP。

### 2.3 Revert 撤销与 Hotfix 应急补丁（提炼 诚实边界与应急排错启发式）
- **线上故障回滚 (Reverts)：** 被 Revert 的代码直接代表最高危的**致命反模式 (Fatal Anti-Patterns)**。
- **紧急热修复 (Hotfixes)：** Hotfix 提交说明中记录的 Root-Cause 排查思路与最小化修复补丁，是提炼“排错心智模型”与“架构诚实边界”的最强样本。

### 2.4 PR 描述模板与架构演进上下文（提炼 架构设计理由与心智模型）
- PR Description 中陈述的“设计考量、选型权衡、破坏性变更说明与替代方案对比”，直接映射为工程师的高阶**决策启发式 (Decision Heuristics)**。

## 4. 核心机制一：基于 Git 轨迹与交互记录的个人/团队技能蒸馏

### 4.1 双层解耦存储架构
- **Part A: 长期记忆事实库 (Self Memory)：** 
  - 从 Git 历史中自动统计：最常修改的模块、高频依赖库版本、提交信息规范（Conventional Commits 模式）、分支管理模型。
- **Part B: 五层行为人格模型 (Persona)：**
  - **第一层（硬规则 Hard Rules）：** 从历史 PR Review 打回意见与 Revert 记录中提取的绝不可违背的红线。
  - **第二层（身份与立场）：** 团队技术倾向（如偏好小步提交、契约优先、不可变数据流）。
  - **第三层（交互与表达）：** 与 AI 协同的表达习惯、PR 描述结构偏好。
  - **第四层（决策启发式）：** 从 PR 方案选型与重构提交中提炼出的架构折中逻辑。
  - **第五层（人际与边界）：** 代码审查标准、提问追问深度与严谨度。

### 4.2 交互态与 Git 变更增量热修复
- **交互态纠偏：** 对话中指出修正（如：“在当前微服务模块下禁止直接查库”），秒级写入热补丁。
- **Git 触发热修复：** 当某次 PR 在评审中被多次指责同类问题时，系统自动将该审查意见转化为增量补丁，推送给全员的技能资产库。

## 5. 核心机制二：Agent 行为精准控制与防御中枢

### 5.1 运行时四级优先级装配协议
在构建发送给底层大模型的上下文时，系统严格按照约束力由高到低进行装配：
1. **最高级（Hard Rules 硬规则）：** 从 Git Revert 与安全红线沉淀的强制禁令，前置于最顶层。
2. **次高级（Role SOP & RIA++ 流程）：** 从 Git 原子提交序列与专家经验提炼的标准执行步骤。
3. **第三级（Personal Twin 画像）：** 工程师个人的编码风格与辅助偏好。
4. **动态级（Runtime Hotpatches）：** 针对当前任务或近期 PR 评审指出的最新增量约束。

### 5.2 行为防御网设计
- **反模式拦截器 (Anti-Pattern Linter)：** 若 Agent 生成的代码命中了从历史故障 Hotfix 中提取出的模式，直接判定执行失败并强制触发自我反思重构。
- **诚实边界与主动熔断 (Honesty Boundary Trigger)：** 遇到信息不足（如缺少接口版本号、缺少数据库表索引信息）时，强制 Agent 中断并向工程师追问，严禁凭空盲目推断。

## 6. 核心机制三：多职业技能提炼与标准化矩阵

### 6.1 结合 Git 的 6-Agent 认知提取工作流
1. **架构提取器：** 从大型重构 PR 与模块依赖变更中抽取系统架构分层与契约设计。
2. **排错提取器：** 从 Hotfix 提交、Issue 关联关闭记录与时序排查 Diff 中抽取排错逻辑。
3. **安全提取器：** 从安全合规审计 PR、依赖漏洞升级提交中抽取防御性编程规范。
4. **性能提取器：** 从性能优化专门 PR（如 SQL 优化、内存泄漏治理）中抽取优化启发式。
5. **反模式提取器：** 从历史被 Revert 的 Commit 及 PR Review 否定性评审中抽取反模式。
6. **边界提取器：** 从 PR 描述中的“已知限制/未覆盖场景”中抽取方法的适用边界。

### 6.2 内置多职业标准化技能矩阵

| 职业角色 | 技能标识 | 核心心智模型 (来自专家与架构PR) | 核心硬规则 (来自PR Review与Revert) | 诚实边界 (来自Hotfix与边界设计) |
| :--- | :--- | :--- | :--- | :--- |
| **前端架构师** | `role.frontend.state-machine` | 显式状态优于隐式推导；状态机是转移的单一真理源。 | 超过 3 个状态分支强制使用状态机；禁止在循环中声明 Hooks。 | 缺失服务端推送时钟协议时，严禁前端自行加延迟推断先后。 |
| **DevOps / SRE** | `role.sre.canary-rollout` | 渐进式暴露风险；指标可观测性先于切流动作。 | 灰度放量未配置自动化指标熔断（Error Rate / Latency）严禁全量上线。 | 缺失全链路监控看板时，必须终止自动上线流程并请求人工介入。 |
| **安全审计员** | `role.security.defense-in-depth` | 零信任架构；所有外部输入均默认视为恶意载荷。 | 严禁在查询层动态拼接未过滤参数；敏感业务数据必须执行脱敏。 | 涉及高危系统指令调用时，禁止自主执行，必须弹出二次鉴权。 |
| **全栈工程师** | `role.fullstack.bff-contract` | 契约驱动设计；数据 Schema 是前后端解耦的单一契约。 | 接口变动前必须先更新 Schema 契约并同步生成双端类型，再改实现。 | 针对未版本化的遗留老接口，拒绝隐式适配，强制要求补充契约。 |
| **个人专属分身** | `personal.twin.my-habits` | 架构整洁至上；偏好不可变数据流与正交解耦。 | 遵循个人命名、目录结构与错误封装习惯；禁止全局隐式副作用。 | 面对超出自身技术栈认知的需求，主动标明推断属性并由人工复核。 |

## 7. 核心机制四：质量保障与达尔文棘轮演进机制

### 7.1 Git 历史回测与诱饵对抗测试集
- **Git 历史回测 (Backtesting)：** 将过去 1 年中优秀的 PR 题目或典型 Bug 任务作为回测试卷，验证 Agent 在加载当前 Skill 后产出的方案是否与高阶工程师的最佳实践相符。
- **负向诱饵用例 (Distractors)：** 输入形式相似但不适用当前架构规范的需求，验证 Agent 是否能准确识别并拒绝误触发。

### 7.2 Darwin 棘轮演进决策流
新规则只有在 **Git 历史回测集 + 对抗诱饵集** 上的综合评分实现单调递增时，才被允许合并入主干资产库；若出现规则冲突或评分下降，系统自动回滚，确保组织认知资产“只增不退”。

## 8. 标准技能描述模板 (No-Code SKILL.md 规范)

```markdown
---
id: "role.category.skill-name"
name: "技能中文名称"
version: "1.0.0"
role: "职业角色分类"
triggers:
  keywords: ["关键词1", "关键词2", "技术名词"]
  intent_patterns: ["用户意图句式1", "用户意图句式2"]
git_sources:
  sample_prs: ["#1024", "#1288"]
  revert_references: ["commit-abc1234"]
dependencies: ["依赖的其他技能ID"]
conflicts: ["互斥禁用的技能ID"]
---

# 1. Hard Rules (最高优先级硬规则 - 沉淀自 PR Review 阻塞意见)
- [规则 01] 必须无条件执行的红线底线。
- [规则 02] 绝对禁止执行的危险行为或架构破坏操作。

# 2. Mental Models & Heuristics (心智模型与决策启发式 - 沉淀自架构 PR 方案)
- **心智模型:** 该领域高阶专家看待该问题的核心认知框架。
- **启发式决策法则:**
  - 当面临情境 A 与情境 B 权衡时，默认优先选择方案 A。
  - 触发某种阈值时，自动采用特定的架构设计模式。

# 3. Execution SOP - RIA++ (可执行步骤 - 沉淀自原子提交序列)
- **触发场景 (A2):** 精确的技术上下文与任务特征。
- **执行步骤 (E):**
  1. 第一步：上下文断言与输入合法性校验。
  2. 第二步：核心架构或业务模型建立。
  3. 第三步：标准流程执行与结果产出。
  4. 第四步：防御性验证与自动化单测覆盖。

# 4. Boundaries & Anti-Patterns (诚实边界与反模式 - 沉淀自 Revert 与 Hotfix)
- **适用边界:** 仅在何种环境、规模或架构分层下生效。
- **诚实边界 (Honesty Trigger):** 遇到何种信息缺失时，必须中断执行并主动向人类提问。
- **反模式清单 (Anti-Patterns):**
  - ❌ 禁止做出的典型初级错误模式 A。
  - ❌ 禁止采用的临时伪修复方案 B。

# 5. Runtime Corrections (运行时热修复增量)
<!-- 由交互纠偏指令与近期 PR 审查自动追加，支持版本溯源与回滚 -->
- [patch-YYYYMMDD-01] (author): 具体的增量修正规范。
```

## 9. 全生命周期落地推行 SOP 与路线图

- **阶段一（第 1 周 · Git 历史挖掘与个人画像初始化）：**
  - 扫描工程师近 3~6 个月的 Git 提交树、PR 评审评论与交互会话。
  - 提炼个人编码习惯与高频技术事实，初始化 `Self Memory` 与 `5层 Persona`。
- **阶段二（第 2 周 · 团队 PR/Revert 规则提取与标准化）：**
  - 重点分析团队近 1 年被 Request Changes 的 PR 与生产 Revert 记录，提取关键 Hard Rules 与 Anti-Patterns。
  - 转化为标准的 `SKILL.md` 资产包，并配齐基于历史 PR 的回测与诱饵测试集。
- **阶段三（第 3 周 · 网关拦截与热修复集成）：**
  - 在 IDE 与 Agent 交互环境中接入控制网关，前置 Hard Rules 约束。
  - 启用日常交互中的实时纠偏命令，实现个人与团队规则的秒级打补丁。
- **阶段四（第 4 周及以后 · Git CI/CD 棘轮自动化演进）：**
  - 将技能评测接入 Git 仓库 CI/CD 流程。
  - 每当发生高质量 PR 合并或新规则提案时，自动触发棘轮评测，实现技能资产库的持续正向增量演进。
