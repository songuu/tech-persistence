# 项目基础架构规则

> Claude Code 执行本规则前，先读取 `.claude/project-standards.json`，确认本文件属于当前 manifest 的受管资产。

## 稳定不变量

- 先读取真实目录、入口、依赖清单、配置、测试和脚本，再描述架构；示例和占位符不是项目事实。
- 仓库内现有约定、生成器和验证命令优先于新造流程；无法证明时明确标为推断或未知。
- 保持变更最小且职责单一，复用已有抽象，但不为尚未出现的需求预建扩展点。
- 业务语义必须体现在模块、类型和函数命名中；错误必须保留操作、对象和失败原因等上下文。
- 不把密钥、令牌、个人数据或生产凭据写入源码、日志、示例和项目规范资产。

## 架构边界

- 明确源码、生成产物、配置和运行态文件的权威来源；只修改权威来源，再用既有流程生成投影。
- 依赖指向稳定接口，避免跨层读取内部文件、隐式全局状态或循环依赖。
- 输入在信任边界处验证，副作用集中在可识别的适配层；核心逻辑保持可独立测试。
- 保留用户文件、未提交改动和兼容承诺；破坏性、不可逆或外部可见操作必须有显式门控。

## 验证

- 先运行覆盖改动的最窄检查，再按风险扩展到类型、单元、集成、构建或端到端验证。
- Bug 修复需要能在修复前失败、修复后通过的回归证据；高风险边界同时验证失败路径。
- 分开报告代码失败、环境阻塞、未验证项和外部状态；本地通过不等于部署或用户侧完成。
- 交付时列出实际改动、执行过的验证、残余风险和可复现命令。
